## 1. P0 · 三处「循环里 await」——只有一处该动

扫全仓得到 3 处 `for` 循环内串行调用后端：

| 位置 | 方法 | 该不该改 |
| --- | --- | --- |
| `tools/WorktreesTab.vue:85` | `getWorktreeDiskUsage` | **该改**：纯读取，每个工作树走一次磁盘统计 |
| `BranchesView.vue:742` | `deleteBranch` | **不该改**：写操作 |
| `tools/MaintenanceTab.vue` | `toggleGitHook` | **不该改**：写操作 |

后两处串行是**正确设计**——并发改 git 索引/配置会撞车，慢一点换取确定性是划算的。这条要写下来，否则下一个会话看到「循环里 await」会顺手"优化"成 `Promise.all`，引入竞态。

第一处是纯读取。10 个工作树 = 10 次往返，每次都在统计目录大小（大仓库单次数百毫秒）。做法：

- 前端限并发（4 路）而不是全并发：全并发会把 505 个 RPC 的服务端同时压满
- 每个结果到达即写入 `worktreeUsageMap`，不必等全部完成才渲染
- 单个失败仍静默跳过（现状如此，保留），但**至少记一次**——现在 `catch {}` 连日志都没有

**验收**：12 个工作树的仓库里，磁盘列填充完成时间从 `N × 单次` 降到接近 `ceil(N/4) × 单次`；打开面板时列表先出现、数字随后逐个填上，而不是整块空白等着。

## 2. P1 · Toast 堆叠 + 可撤销（唯一的交互欠账）

`useToast.ts` 现在是后到覆盖先到。连点两次"已储藏"，前一条直接消失——用户无法确认第一次是否成功。

要做：

1. **环形队列**，最多同时 3 条，超出时最早的让位（不是被挤掉，是自动淡出）
2. **写操作可撤销**：后端 `UndoLastOperation` 已存在，但只有操作日志页接了。储藏 / 丢弃单文件 / 暂存这类可逆操作，toast 上给「撤销」，5 秒有效
3. 堆叠时的进入/退出动画要错开，否则三条一起滑入像闪烁

**验收**：连续触发 3 次操作，三条都在，各自倒计时；点第 2 条的撤销只回滚第 2 次；超过 3 条时最早的一条先走。

## 4. P3 · 9 项「只报不修」——分两类，只做能可靠做的

`git_asset_*` 的 5 个审计（LOD / Lightmap / 材质覆盖 / 贴图通道 / 物理碰撞）是**按扩展名和大小做的启发式扫描**，不解析 `.meta` / `.uasset`。它们不知道正确的目标值是什么，自动改写只能靠猜，改坏会让 Unity 项目打不开。

所以：

### 4.1 只产建议（4 项，安全）

| 审计 | 产出 |
| --- | --- |
| `AuditLocalizationParity` | **已完成**：`GenerateLocalizationKeyPatch` 输出 json/csv/ts 片段 |
| `DetectAssetCyclicDependencies` | 断环建议（去掉哪条引用代价最小）+ 引用链路径 |
| `AuditSymbolsAndDefines` | 冲突矩阵 + 建议保留值；改 `ProjectSettings` 交给人 |
| `AuditNativePluginsAbi` | 「插件 × 平台」ABI 兼容表 + 升级路径 |

### 4.2 加「导出行动清单」（5 项，统一的出口）

这 5 项不做自动修复，但**用户至少能把问题带走**：一个通用 RPC，把任一审计结果导成 Markdown 清单（含文件路径、当前值、建议值、依据），供人工处理或贴进 issue。

比写 5 个不可靠的文件改写器有意义，也比现在「看到问题、无处可去」好。
