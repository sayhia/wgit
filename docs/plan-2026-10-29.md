## 1. 三个判断

### 1.1 广度已经过饱和，继续加 RPC 是负收益

`docs/feature-research-2026-10.md` 在两周前就写了「广度饱和，横向扩张边际收益趋零」，并给出「明确不做：再补 50 个 RPC」。实际上这两周 RPC 从 388 涨到 501。

这不是说新增的 113 个都没价值，而是：**每新增一个能力，就多一个需要维护、需要三态、需要 i18n、需要测试的面**。当前 137 个组件、951 条测试已经是单人或双人维护的舒适区上限。

### 1.2 最大的空转是「只报不修」

`feature-research` 2.3 指出 36 个 `Audit*`/`Lint*`/`Detect*` 里有 14 项是断头路。今晚实测复核了其中 13 项：

```
AuditLocalizationParity          — 仍只读
AuditLodStreaming                — 仍只读
AuditTextureChannelPacking       — 仍只读
AuditLightmapBakeSettings        — 仍只读
AuditMaterialInstanceOverrides   — 仍只读
AuditPhysicsMeshCollision        — 仍只读
AuditSymbolsAndDefines           — 仍只读
DetectAssetCyclicDependencies    — 仍只读
AuditCommitContentSafety         — 仍只读
CheckStagedNonLfsLargeFiles      — 仍只读
GetLfsLockActivity               — 仍只读
RunRepoHealthCheck               — 仍只读

```

**13 项里只补了 1 项。** 用户看到「LOD 梯队不达标」「材质实例覆盖过多」，界面上没有任何能改的按钮——这比没有这个功能更差，因为它消耗信任。

### 1.3 伪实现已经处理得当，不用再动

`git_parity_honesty_test.go` 已经锁住：对等中心不得声称认证、徽章必须免责、不得伪造签名与测试数、外部集成必须写明限制。这是正确的处理方式（标注而非删除），不需要重做。

## 2. P0 · 把「只报不修」接上（本轮主体）

按**写入风险**分三批，不是按功能分类。理由：改 Git 自身状态可以撤销，改用户业务文件（`.unity`/`.meta`/贴图）不能。

### 批 1 · 只动 Git 状态，可撤销（3 项）

| 断头路 | 补的写操作 | 做法 | 验收 |
| --- | --- | --- | --- |
| `CheckStagedNonLfsLargeFiles` | `ConvertStagedLargeFilesToLfs` | 生成/追加 `.gitattributes` → `git rm --cached` → `git add` 走 LFS；**不碰工作区文件内容** | 审计里「3 个大文件未走 LFS」旁边出现「转为 LFS」；执行后同一审计变为 0；`git lfs ls-files` 能列出 |
| `GetLfsLockActivity` | `BreakStaleLfsLocks` | 复用已有的批量破锁逻辑（`LfsBulkUnlockResult` 已存在），把入口从锁面板挪/复制到 LFS 活动卡 | 僵尸锁计数旁有「批量破除」；执行后计数归零；失败项逐条列出原因 |
| `AuditCommitContentSafety` | `SaveCommitSafetyRules` | 把 5 个硬编码词改成可配置规则（JSON 存 `.git/wgit-rules.json`），审计读它 | 设置里能增删规则；改完审计立即用新规则；规则文件损坏时回退默认值并有提示 |

**共同要求**：三者都必须先 `dry-run` 再确认——返回「将要改哪些文件/哪些锁」，用户确认后才落盘。已有 `useConfirm` 的 `impact` 参数可用。

### 批 2 · 写业务文件，必须备份（5 项）

| 断头路 | 补的写操作 | 关键约束 |
| --- | --- | --- |
| `AuditLodStreaming` | `FixLodGroups` | 改 `.meta` 前整目录备份到 `.git/wgit-backup/<ts>/`；只改 LOD bias 与 screen relative height 两个字段，其余原样写回 |
| `AuditLightmapBakeSettings` | `FixLightmapSettings` | 同上；只动 `lightmapResolution` / `lightmapPadding`，不重建场景 |
| `AuditMaterialInstanceOverrides` | `ResetMaterialOverrides` | 重置为父材质默认值；列出将清除的参数名，供勾选 |
| `AuditPhysicsMeshCollision` | `SimplifyMeshColliders` | **不做自动减面**（会改变物理行为）——只把 `Convex` 切换成 `ConvexHull` 或反向，并给出「需人工验证碰撞」的提示 |
| `AuditTextureChannelPacking` | `RepackTextureChannels` | 只做「POT 转换 + 通道重排」中的**建议生成**，实际写文件放到批 3 |

**共同要求**：
- 一律 `dry-run → 预览 diff → 确认 → 备份 → 写入 → 回读校验`
- 每个 fix 返回 `BackupDir`，修复中心显示「可回滚到此备份」
- 写入失败时**不允许部分成功**：先写临时文件，全部成功才 rename

### 批 3 · 只产出建议，不代做（4 项）

这四项即使做了也不该自动执行——它们要么需要人判断，要么跨系统。

| 断头路 | 产出 |
| --- | --- |
| `AuditLocalizationParity` | 生成缺失 key 的 CSV + 一份可直接粘贴的 `.ts` 片段；**不写语言文件** |
| `DetectAssetCyclicDependencies` | 输出断环建议（去掉哪条引用代价最小）+ 引用链路径；不自动删引用 |
| `AuditSymbolsAndDefines` | 输出冲突矩阵 + 建议保留值；改 `ProjectSettings` 交给人 |
| `AuditNativePluginsAbi` | 输出「插件 × 目标平台」ABI 兼容表 + 升级路径链接；不做下载替换 |

**验收（三批统一）**：每项都要有
1. 一条审计 → 执行 → 复审变绿的完整路径测试（`httptest` 或临时仓库）
2. `dry-run` 不产生任何文件变更（可用 `git status --porcelain` 前后比对断言）
3. 失败路径：权限不足 / 文件被占用 / 磁盘满，至少覆盖一种

## 5. P3 · 工程与协作（比功能更急）

### P3.1 并发写入是当前最大的质量风险

`plan-2026-10-28` 的记录里已经出现过一次：两个会话同时改，导致 `CrashReportModal` 带材质缺陷进主干、工作区 3 处红。

今晚又出现一次：并发会话新增的组件用了 21 个 `t()` key，但 catalog 没同步，`bun test` 直接红。**守卫是有效的，但它只在提交后才发现。**

做法：
- 按目录切分写入权（一人 `frontend/`、一人 Go 侧），或串行
- 每次 `git commit` 前跑全量（`go test . && cd frontend && bun test tests && bun run typecheck`），而不是只跑自己关心的
- 把这条写进 `docs/release-checklist.md`

### P3.2 `git_service.go` 需要继续拆

178 个方法在一个文件里，占全部 RPC 的 35%。项目约定写着「不要继续往里塞」，但它仍在长。

做法：只做**按域搬移**，不改逻辑。每次搬一组（如「标签相关 12 个」→ `git_tags.go`），搬完跑全量测试。分 5~6 次提交完成，不要一次性重构。

### P3.3 i18n 协作守卫前移

现在「用了 key 但没加 catalog」只在测试里发现。可以在 `bun run build` 前加一个 pre-flight 脚本，或者更简单：让 `t()` 在 DEV 下对缺失 key 打 `console.warn` 一次——开发时即时可见。

## 7. 明确不做

- **继续加 RPC**（501 已过饱和；本计划 P0 补的是写操作，属于把断头路接通，不是新增能力面）
- 主题编辑器 / 自定义 CSS（打破对比度契约）
- 第三方 UI 组件库（20 个 `ui/` 已统一）
- 删除 9 个伪实现（已被 `parity_honesty_test` 约束为诚实自报，删除反而丢失「我们知道自己缺什么」的信息）
- 自动减面 / 自动改物理（会改变运行时行为，必须人来判断）
