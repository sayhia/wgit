## 为何本轮不拆

- **Go**：`git_service.go` 是无状态值接收器 + **已冻结**（只修不增，新能力进 AiService/AssetService），拆分的核心动因（止血增长）已被服务化消解；存量整文件搬迁会扰动 rpcCoverage 口径与大量既有测试，收益低于回归风险。**测试覆盖到的函数级抽离（同包新文件、逐块搬移、每步 `go build` + `go test` 全绿）随时可做；整文件一次性搬迁本轮不做。**
- **Vue**：五个文件都是「拆过一轮又反弹」，说明痛点不是静态结构而是能力持续流入；无新功能落地时纯搬移只会制造 diff 噪声。先抽 composables（状态/事件逻辑）再拆模板块才是有效路径。

## 未来拆分准入条件（满足全部才动）

1. 单文件职责块 **>8 个**，或 Go >5,000 行 / Vue >100KB 连续两轮战役无下降趋势；
2. 对应域测试覆盖率 **>70%**（Go 主包当前 77.8% 已达标；Vue 需先补该组件的契约测试）；
3. 拆分仅以函数级/子组件级抽离进行，每步构建与全量测试通过后独立提交，可二分回滚。
