UGIT DESIGN SYSTEM · 2026

为高频 Git 操作而设计

一套面向游戏研发与美术团队的设计语言：在 320px 的窄栏里保持信息密度，在历史、差异与锁状态之间保持视觉可辨。所有颜色、字号、间距与动效都由令牌驱动，深色与浅色主题共享同一套语义。

01 · FOUNDATION

设计原则

四条原则决定取舍：当密度与美观冲突时，先保证可读与可辨；当新样式与既有语言冲突时，先复用令牌。

信息优先

先让状态、路径、增删行可读，再考虑装饰。任何降低信息密度的留白都必须换来更清晰的层级。

密度可控

以 4px 为基线，紧凑模式行高 24px、舒适模式 32px。密集列表允许 10–11px 字号，但正文不低于 10px。

状态可辨

成功、警告、危险、信息各有固定色相与底色；颜色永远与文字或图标同时出现，不单独承载语义。

一致可预期

同样的动作使用同样的控件与位置：主操作在右、危险操作需确认、弹窗标题栏统一 44px、关闭永远在右上。

02 · COLOR

色彩系统

深色是产品默认主题。表面由「画布 → 卡片 → 抬升 → 浮层」四级构成，边框只使用一种中性色；语义色分「文本色 / 浅底色 / 边框色」三件套，避免半透明叠加造成的色差。

表面与边框

bg-canvas 应用画布、历史表格、差异区 #0d1117 / #f6f8fa
bg-surface 卡片、侧栏、弹窗、输入框外层 #161b22 / #ffffff
bg-raised 次级按钮、表头、选中态、分段控件轨道 #21262d / #eaeef2
bg-overlay 悬浮层、弹窗页脚、提示条 #1c2128 / #f0f3f6
border-default 唯一默认边框色；悬停升至 border-strong #30363d / #d0d7de

文本

语义色

色相五阶色阶

每个色相都提供同一套五阶：<hue> 文本色 → -bg 浅底 → -bg-strong 强调底 → -strong 实心填充 → -strong-hover 实心悬停。实心悬停必须比静止态更深（Tailwind 默认的 600 → 500 是变浅，会把白字对比度压到 3.3:1）。

按钮两种形态

实心按钮 · solid主操作
主操作 提交 删除

bg-<hue>-strong hover:bg-<hue>-strong-hover text-inverse

色调按钮 · ghost → filled次要操作
忽略 运行 GC 丢弃

bg-<hue>-bg text-<hue> hover:bg-<hue>-strong hover:text-inverse

静止态用浅底 + 色相文字；悬停整块填实并反白 —— 两种状态都能落在 4.5:1 以上，而「浅底再加深一点」在浅色主题下必然跌破 AA。

提交类型色

类型色只用于徽章：文本色 + 浅底色 + 32% 透明度描边。新增类型必须从现有色相中选择，不引入新色。

05 · MOTION

动效

动效只用于解释「什么发生了变化」：弹窗入场、列表增删、状态切换。默认 160ms，不做弹跳，不阻塞操作。

缓动曲线EASING
cubic-bezier(0.22, 1, 0.36, 1)

入场先快后缓，强调「到达」；prefers-reduced-motion 下关闭全部动画。

06 · COMPONENT

按钮

一屏最多一个主按钮。主操作用实心蓝/绿，次级用抬升底色，危险操作需二次确认。悬停色已按 AA 对比度重新校准（旧版 #388bfd 白字仅 3.34:1）。

变体与尺寸28PX DEFAULT / 24PX SM / 32PX LG

✓ 应该

  • 主按钮每屏 ≤ 1 个，位置固定在右下或提交框底部
  • 悬停背景加深而非变亮，保证白字对比度 ≥ 4.5:1
  • 危险按钮文案写清后果：「放弃 3 个文件」

✗ 避免

  • 用琥珀底 + 白字作为按钮（2.52:1，不可读）
  • 同一区域并排三个以上实心按钮
  • 仅靠颜色区分主次，忽略文案与位置

16 · IMPLEMENTATION

实施与迁移

令牌文件是唯一真源：新代码引用 CSS 变量；存量 Tailwind arbitrary 值按映射表逐步替换，不要求一次性重写。

使用令牌

/* 1. 引入令牌（深色为默认） */
@import "./design-system/tokens.css";

/* 2. 组件只消费语义令牌，不写死颜色 */
.panel {
  background: var(--ug-bg-surface);
  border: 1px solid var(--ug-border-default);
  border-radius: var(--ug-radius-lg);
  color: var(--ug-text-primary);
}

/* 3. 主题切换只改 data-theme */
<html data-theme="light">

贡献流程

1 · 提议

新增令牌需说明使用场景、对比度验证结果，以及为什么现有令牌不适用。

2 · 评审

检查命名是否符合 --ug-<类别>-<角色>，是否同时提供深浅两套值。

3 · 发布

更新令牌文件与本页示例，记录版本变更；破坏性改动需升主版本号。
